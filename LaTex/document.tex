	\section{Introducción}
	
	En este informe se comenta el desarrollo de un programa a nivel de usuario que interactúa con el sistema operativo a través de operaciones de \textbf{Entrada y Salida (E/S)} para manipular archivos y flujos de texto. Específicamente, se construyó un transpilador (traductor de código fuente a código fuente) escrito en Rust, capaz de leer un archivo de JavaScript (\texttt{.js}), procesarlo línea por línea, y emitir el código fuente equivalente en Rust (\texttt{.rs}) a través de la salida estándar (\texttt{stdout}).
	
	Es importante destacar que este código solo actua como un traductor, a diferencia de un intérprete o una Máquina Virtual, el programa \textbf{no ejecuta} la lógica del código, sino que se limita a traducir la sintaxis y mostrar el nuevo código, delegando la responsabilidad de compilación y ejecución al usuario leyendo el texto de salida.
	
	\subsection{Objetivos de la Solución}
	\begin{enumerate}
		\item \textbf{Gestión de Archivos (Abstracción del S.O.):} Utilizar las llamadas al sistema nativas de la librería estándar de Rust (\texttt{std::fs}) para acceder a un archivo almacenado en el disco y cargarlo en la memoria principal para su procesamiento.
		\item \textbf{Procesamiento de Cadenas y Flujos de Salida:} Analizar el archivo leído para identificar palabras clave de JavaScript (\texttt{function}, \texttt{const}, \texttt{console.log}), reemplazarlas por sus equivalentes en Rust (\texttt{fn}, \texttt{let}, \texttt{println!}) e imprimir el resultado interactuando con la salida estándar del sistema operativo.
	\end{enumerate}  
	
	\subsection{Descripción del problema}
	El lenguaje JavaScript es notoriamente conocido por ser un lenguaje interpretado lento, ejecutado históricamente en navegadores y hoy en día a través de entornos como NodeJS donde suele ser menos eficiente en consumo de recursos en comparación a lenguajes compilados a nivel de sistema como Rust. El problema abordado es cómo leer un bloque de código básico de JS y transformarlo a Rust utilizando operaciones de E/S, soportando un set limitado de instrucciones: creación de variables, creación de funciones, \texttt{console.log} y sumas.

	\section{Contexto Teórico y Relación con el Sistema Operativo}
	
	El problema se modela considerando el manejo de memoria, la entrada/salida y la gestión de procesos del sistema operativo.
	
	\begin{itemize}
		\item \textbf{El Proceso:} Cuando se ejecuta el comando \texttt{cargo run}, el sistema operativo asigna memoria RAM y crea un hilo de ejecución principal en modo usuario para el programa transpilador.
		\item \textbf{Salida (Consola):} Al utilizar \texttt{println!}, el programa vuelve a solicitar al S.O. que tome las cadenas procesadas en la RAM y las escriba en el búfer de salida estándar (\texttt{stdout}), mostrando el código final en la terminal del usuario, cosas de compiladores, donde no nos tenemos que preocupar de las interacciones duras del SO.
	\end{itemize}

			\section{Resultados y Ejecución}
			
			El programa fue compilado y ejecutado utilizando el gestor \texttt{cargo}. En la ejecución, el proceso solicitó el archivo \texttt{codex.js} al S.O., realizó las mutaciones sintácticas y emitió el resultado mediante la salida estándar.

			
			Como se observa, el programa finalizó exitosamente e imprimió en consola el código fuente transpilado y válido para Rust. \textbf{Es vital notar que el código de la suma matemática no se ejecutó en ningún momento durante este proceso}. El programa actuó exclusivamente como un manipulador de texto: leyó un archivo, reemplazó caracteres, y escribió un nuevo flujo de texto en la terminal.

			\section{Conclusión}
			
			El desarrollo de este transpilador básico permitió observar en la práctica conceptos de la arquitectura de Sistemas Operativos, específicamente el manejo de la Entrada/Salida (E/S) y la diferencia entre procesar texto y ejecutar código.
			
			En primer lugar, se evidenció el rol del S.O. como \textbf{proveedor de abstracciones}. Nuestro programa en Rust no tuvo que calcular en qué bloque físico del disco se encontraba el archivo \texttt{codex.js}; la llamada a la librería estándar (\texttt{std::fs}) encapsuló las peticiones al hardware en modo Kernel, demostrando cómo el sistema operativo oculta la complejidad del hardware al programador.
